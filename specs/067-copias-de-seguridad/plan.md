# Plan 067 — Copias gestionadas por Coolify

1. Conservar la configuración actual de medios y la migración de base ya publicada. Retirar la pantalla, la ruta interna y el programador de Vocero.
2. Comprobar si el PostgreSQL del Compose está registrado como recurso de base para el respaldo nativo. En staging, Coolify devuelve una lista vacía de recursos de base. Empaquetar `pg_dump`, `pg_restore`, AWS CLI y el comando de copia en el target Coolify de la imagen `app`. El resto de imágenes conserva sus dependencias.
3. Configurar el bucket privado de copias con un token de objetos propio, por instancia. Guardarlo como variables de ejecución y crear la tarea en Coolify para el servicio `app`. Usar `0 */8 * * *` en la zona del servidor. Un bloqueo en el volumen evita que dos ejecuciones se solapen.
4. Generar un dump comprimido, comprobar su catálogo, subirlo y comparar el SHA-256 del objeto remoto antes de publicar el manifiesto. Configurar retención de 30 días y expiración de cargas incompletas con reglas R2 por prefijo. Revisar el historial de tareas y comprobar la última copia antes de ampliar el despliegue.
5. Proteger los medios por separado. Conservar los binarios históricos y de contingencia en una copia privada. Validar la restauración, copiar los archivos a sus claves existentes y verificar desde la aplicación. Ejecutar la limpieza confirmada únicamente dentro de una ventana sin cambios de medios.
6. Ensayar desde staging con PostgreSQL desechable y datos de prueba. Registrar el SHA, el ID de copia, la verificación remota, el resultado de restauración y la comprobación de adjuntos.
